# RQ3 讲解：评估规则会不会把「事后报警」算成「提前预警」（入门版）

日期：2026-11-10。这是讲解，不是新结果。`l.xxx` 是冻结投稿版的 PDF 页边行号，原文在本目录的 `论文全文_抽取.txt`。
配套讲解：`11-10_Table3模型怎么训练_讲解.md`，讲 Table 3 的模型怎么训练、分数从哪来。

---

## 0. 一句话

**RQ3 问的是：现在文献里常用的评估方法，会不会让一个只会「事后报警」的模型，看起来像会「提前预警」？**

做法是：**模型的报警一个都不动，只换评分规则**，看分数变多少。分数变了，报警时间却没变，那变的那部分就只能来自评分规则本身。

打个比方：同一份考卷，答案一个字不改，换三套评分标准各批一遍。如果某套标准下分数从 36 分涨到 177 分，那多出来的分数是标准给的，不是学生答出来的。

---

## 1. 背景：两种常见的「评估习惯」

先回忆两个概念（`11-10` 前面讲过）：

```text
         9:50          10:00 (onset，异常开始)        10:20
  ── 正常 ──┼── Pₑ 前兆窗口 ──┼──────── Aₑ 异常段 ────────┼── 正常 ──
```

- **检测（detection）**：异常开始后报出来就算对。目标是 Aₑ。
- **预警（early warning）**：要在 onset **之前**报出来。目标是 Pₑ（benchmark 上取 onset 前 100 步）。

文献里想评「预警」时，常用两个习惯（l.012–014、附录 A.1 l.654–663）：

### 习惯 1：标签前移（shifted label）

把异常标签往前挪 W 步，让 onset 前那一段也算「正类」，也就是把目标改成 Pₑ ∪ Aₑ（论文式 (4)）。

问题在于，这个目标只取决于**离 onset 有多远**，和那段数据里有没有前兆无关。论文 l.671–674 指出：一个**完全不看数据**、只知道「离 onset 还有几步」的预言器，就能在这个目标上拿满分。

### 习惯 2：点调整（point adjustment，PA）

**一个正类区间里，只要有任何一个点报了警，整个区间都算报中。**（论文式 (5)）

```text
标签：  0 0 1 1 1 1 1 0
报警：  0 0 0 0 0 0 1 0     ← 只在最后一个点报了警
PA 后： 0 0 1 1 1 1 1 0     ← 整段算报中
```

**两个习惯叠在一起就出问题了**：目标是 Pₑ ∪ Aₑ 时，onset 之后（在 Aₑ 里）才报的警，经过 PA 会被一路扩回 Pₑ。纸面上看像「提前预警了」，可报警时间一点没变（l.251–252）。

## 2. RQ3 的设计：只换规则，不动报警

l.255–259 写的是：

1. **冻结**：模型分数、归一化、阈值全部固定。所以每个时刻报不报警，事先就定死了。
2. **只换两样东西**：
   - **评估目标**（拿哪一段当正类），三选一；
   - **计分规则**（加不加 PA），二选一。
3. 每种组合都配一组**不看输入的随机报警**作对照。

> 「目标怎么选、分数怎么记会变，但检测器的输出不变。」（l.259）

### 2.1 三种评估目标

```text
                       Pₑ                     Aₑ
  时间 ─────────┼─── 前兆窗口 ───┼═══════ 异常段 ═══════┼──────
                              onset
  Detection 目标      :                  ███████████████████        只有 Aₑ 是正类
  Shifted-warning 目标:   ██████████████                            只有 Pₑ 是正类（和 Aₑ 不重叠）
  Merged 目标         :   █████████████████████████████████        Pₑ ∪ Aₑ 都是正类
```

| 目标 | 正类是什么 | 对应的问题 |
|---|---|---|
| **Detection**（检测） | Aₑ | 异常发生后报没报出来 |
| **Shifted-warning**（预警） | Pₑ | onset 前那段报没报警 |
| **Merged**（合并） | Pₑ ∪ Aₑ | 文献里「标签前移」的做法 |

### 2.2 加不加 PA

每个目标都算两遍：原始的、加 PA 的。**PA 只在自己的目标区间内扩展**（l.256）：

- Detection + PA、Shifted + PA：量的是**区间内部**被抬高了多少（l.257）。
- **Merged + PA**：直接检验 onset 之后的报警会不会把功劳记到 onset 之前（l.258）。**这是 RQ3 的核心。**

三个目标 × 两种计分 = **6 种评估协议**。Table 3 右边 4 列是其中的 Det.、Det.+PA、Shift.、Shift.+PA；Merged 的两列在 Table 4 和附录 B.4。

## 3. 指标定义

### 3.1 报警

模型每个时刻给一个分数 s(t)，**分数高于阈值 τ 就报警**：

  a(t) = 1[s(t) > τ]

τ 取正常时段分数的 **95 分位**（主结果），也看 99 分位（l.422）。直观地说：正常时段里大约有 5% 的时刻会报警。

⚠️ ⑦ §4 第 6 条：代码里这个「正常时段」取自**测试段**里标为正常的点，论文写的是 normal-only 校准数据，两者不一致。

### 3.2 逐点 F1（Table 3 右半边、Table 4 用的）

把每个时刻当成一道判断题：

| | 模型报警 | 模型没报警 |
|---|---|---|
| **这一刻是正类**（在目标区间里） | TP（报中） | FN（漏报） |
| **这一刻是负类** | FP（误报） | TN |

- 精确率 Precision = TP / (TP + FP)：报了警的时刻里，有多少落在目标区间。
- 召回率 Recall = TP / (TP + FN)：目标区间里的时刻，有多少报了警。
- **F1 = 2·TP / (2·TP + FP + FN)**：两者的调和平均。

汇总方式（l.424）：先把同一个数据集里所有实体的 TP、FP、FN **加起来**，算出这个数据集的 F1；五个数据集再**简单平均**。正文说的「平均 F1」，是再对七个模型取平均（Table 20，l.1115）。

### 3.3 PA 后的 F1

先按 PA 改写报警序列（区间里有一个报中，就整段改成报中），再用同样的公式算 F1。

### 3.4 随机报警对照（附录 B.4.2，l.1111–1114）

| 对照 | 怎么造 | 保留了什么 | 打乱了什么 |
|---|---|---|---|
| **Bernoulli 随机报警** | 每个时刻独立掷硬币，报警概率 = 这个模型在这个实体上的报警率 | 报警的总量 | 报警的时间，以及报警是否连成段 |
| **循环平移** | 把模型自己的报警序列整体平移一个随机距离，从尾部移出去的接回到头部 | 报警总量，以及每段报警的长度和段数 | 报警和事件的相对位置 |

每种各抽 20 次。两者都**完全不看输入数据**，所以它们拿到的分数，就是「瞎报也能拿到的分数」。

**为什么要这两个对照**：随机报警在 PA 下有天然优势。报警率 p = 5%、区间长 100 步时，随机报警至少打中区间一次的概率是

  1 − (1 − 0.05)^100 ≈ 0.994

（附录 l.676–677，正文 l.453）。也就是说，几乎每个区间都会被「打中」，PA 再把整段算成报中。

### 3.5 「只靠 onset 后报警拿分」（late-only）

在 Merged + PA 下被算作报中的事件里，再看它的 Pₑ 段有没有报警。**Pₑ 里一次警都没报**，却因为 Aₑ 里报了警而拿到「预警」的分，就记为 late-only（附录 B.4.1，l.1102–1107）。

### 3.6 决策导向的指标（附录 B.4.4，只在逐机 iForest 上算）

| 指标 | 定义 |
|---|---|
| **Early recall（提前召回）** | 一个事件只有在 onset 前 100 分钟内**新开始**了一段报警，才算提前报到 |
| **Episode precision** | 所有报警段里，开始于合格前兆窗口内的比例 |
| **Episodes** | 正常数据上每 1000 个样本有多少段报警（衡量误报负担） |
| **Alarm time** | 正常数据里处于报警状态的时间占比 |
| **Lead** | 第一次报警比 onset 提前多少分钟（中位数） |

## 4. 结果

### 4.1 Table 3 右边四列（95 分位，七个模型）

| 模型 | Det. | Det.+PA | Shift. | Shift.+PA |
|---|---|---|---|---|
| iForest | 0.283 | 0.676 | 0.047 | 0.193 |
| DAGMM | 0.241 | 0.652 | 0.040 | 0.235 |
| USAD | 0.114 | 0.440 | 0.038 | 0.203 |
| LSTM-VAE | 0.270 | 0.719 | 0.045 | 0.264 |
| AnomTrans | 0.010 | 0.452 | 0.007 | 0.207 |
| FCM | 0.213 | 0.503 | 0.037 | 0.075 |
| A2P | 0.123 | 0.415 | 0.040 | 0.060 |

（l.384–389）七个模型平均下来，Shifted-warning F1 **不加 PA 是 0.036，加了 PA 是 0.177**，报警时间一个都没变（l.428，摘要 l.026–027）。

### 4.2 Merged 目标：onset 后的报警被记成了预警

- Merged 目标的平均 F1：不加 PA 0.175，加 PA 0.570（l.1107）。
- 加 PA 后算作报中的事件里，Pₑ 段**一次警都没报**的比例（l.1104–1106）：

| 数据集 | late-only / 报中 | 比例 |
|---|---|---|
| SMD | 314 / 699 | 0.449 |
| PSM | 22 / 48 | 0.458 |
| SWaT | 28 / 65 | 0.431 |
| SMAP | 87 / 281 | 0.310 |
| MSL | 37 / 181 | 0.204 |

  正文的概括是「20%–46% 的 merged 报中只靠 onset 后的报警拿到预警分」（l.429）。

### 4.3 随机报警对照（Table 4，l.448–451；Table 20）

| 协议 | 七个检测器 | Bernoulli 随机报警 | 循环平移 |
|---|---|---|---|
| Detection + PA | 0.551 | 0.740 | 0.476 |
| Shifted + PA | 0.177 | **0.431** | 0.167 |
| Merged + PA | 0.570 | **0.788** | 0.497 |

- 加了 PA 之后，**完全不看数据的随机报警，分数比每个检测器都高**（l.453–455）。
- 循环平移保留了检测器报警「连成段」的形状，在 Shifted 目标上的分数和检测器接近（0.167 对 0.177）。
- **不加 PA 时**，检测器和同报警率的随机报警，F1 相差在 0.002 以内（l.456）。换了 90/95/99/99.9 四个阈值、W = 25/50/100/200 四个前兆长度，结论都一样（l.1121–1124）。

> 直观解释：随机报警是零散的点，撒得到处都是，PA 下几乎每个区间都能「蹭」到一次；检测器的报警往往成团出现，覆盖的区间数反而少。循环平移保留了成团的形状，所以分数和检测器接近。

### 4.4 对照组：3W（真的有前兆）

在 3W 上，检测器**本来就在 onset 前报警了**，七个模型里有六个，PA 让 Shifted-warning F1 变化不到 0.03；benchmark 上，PA 把这个 F1 抬高了约 5 倍（l.457–459）。

**这说明 PA 本身不一定造假**：真有前兆、模型真提前报了的时候，PA 加不加分都差不多；只有在没有提前报警的地方，PA 才会大幅抬分。

### 4.5 逐机 iForest（SMD，附录 B.4.3–B.4.4）

- Merged F1 加 PA 后翻倍以上（95 分位：0.203 → 0.464），可新开始的报警段的召回率没变；被记为报中的事件里，约四分之一（72/302）在 onset 前没有报警（l.426–427，Table 21）。
- Early recall：随机分数 98.8%，iForest 62.8%，两者的报警段频率相近（44.0 对 46.7 段 / 千样本，Table 22）。所以**只看 early recall，也会奖励频繁报警**（l.430–431）。

## 5. RQ3 的结论（论文自己的说法）

1. **PA 抬高了预警 F1，但没有带来更早的报警**（l.426）。
2. **在 Merged 目标上加 PA，onset 之后的报警会被记成 onset 之前的预警**（l.251–252，l.429）。
3. **抬高的幅度取决于报警率**，随机报警在 PA 下可以拿到比所有检测器都高的分数（l.453–455）。
4. 所以，要评估「预警」，不能只看 shifted label + PA 的 F1。论文的替代方案是：
   - 先用 RQ1 的检验确认这段数据里有前兆（Dₑ = 1）；
   - 再看模型在 Pₑ 里有没有报警（附录式 (6)，l.664–667）；
   - 并始终和同报警率的随机报警比较。
