# ⑧ 解决到哪一步：正常数据被误判成有前兆

> 作业原文：「找一下在正常数据被误判成拥有前兆的数据，判断是不是良性漂移，还是工况改变，能解释清楚检测异常的原因？」
> 对应 rebuttal：审稿人 wxGK 的 W1a / Q1（TRACKER R2-1）。证据来自实验 E-012，完整数字表见 [[11-10_⑧误判窗口证据]]。
>
> 本页的「误判」指：**检验**在标为「正常」的数据上报了警。检验本身只判断「和 fit 段比有没有不同」，这一点它没判错；「误判」是说不该把这次「不同」读成「有前兆」。一个窗口到底算不算误判，要看报警的原因，这正是第 5 节要你判断的。如果报警的地方真有大变化（比如 t_p 标晚了，或者关油嘴这类工况动作被标成了「正常」），那次报警就不算误判，问题出在标签上。

## 一句话

**解决了一半：被误判的数据都找出来了，「检验为什么报警」也说清了；但「这是良性漂移还是工况改变」还没判断。** 这一步留给你，第 5 节每条记录都配了图，看完直接在下面填。

## 1. 先把场景讲清楚

### 数据：3W 是什么

3W 是巴西国家石油公司公开的**海上油井传感器数据**。每口井上装了压力、温度传感器，每秒记一次。

- **一条记录**：某口井的一段连续记录，名字像 `WELL-00025_20200629194141`，意思是「25 号井，从 2020-06-29 19:41:41 开始的那段」。
- **故障**：每条记录最后都会出一种故障。专家在数据里标出了故障「开始过渡」的时刻，论文里记作 **t_p**。t_p 之前标的是「正常」。
- **故障类型**（3W 官方编号）：1 含水率突然升高、2 井下安全阀误关、3 严重段塞流、4 流动不稳定、5 产能快速下降、6 生产油嘴快速堵塞、7 生产油嘴结垢、8 生产管线结水合物、9 气举管线结水合物。

### 实验：wxGK 质疑的那个设计

论文附录做过这样一个检查（l.805–808）：

1. 把每条记录里 t_p 之前的「正常」时段，**按时间顺序切成三等份**：
   - **第一份（fit 段）**：让检验学习「正常长什么样」；
   - **第二份（null 段）**：校准检验，估计它在正常数据上会误报多少；
   - **第三份（verification 段）**：拿来验收。这一份离故障最近。
2. 把 verification 段切成很多小段，每一小段叫一个**窗口**，逐个问检验：「这个窗口和正常一样吗？」
3. 检验回答「不一样」，就叫这个窗口**被拒**（统计检验里「拒绝原假设」的意思，原假设是「和正常一样」）。

**理想情况：** verification 段本来就是正常数据，被拒的比例应该在 5% 左右，也就是检验的正常误报率。
**实际结果：** 论文报的是 29.2%。wxGK 因此问：检验抓到的会不会只是「运行状态变了」，而不是故障前兆？

### 检验看的是什么

检验不直接看原始曲线，而是先算几个**统计特征**（论文里叫「描述子」），再拿这些特征和正常时段比：

| 特征 | 意思 |
|---|---|
| mean（均值） | 这一小段的平均水平，比如平均温度 |
| slope（斜率） | 这一小段在往上走还是往下走 |
| autocorr（自相关） | 曲线自己前后像不像，反映波动的「节奏」 |
| crosscorr（互相关） | 两个传感器之间同步不同步 |
| jump（跳变） | 有没有突然一跳 |

名字后面的 `@w50`、`@w25` 表示在多长的一小段上算的（50 步或 25 步）。

检验大致有两种报警方式：这一段的特征**和正常参照差得远**（偏离）；或者**这一段内部突然变了**（变化）。

### 传感器名字怎么读

只有名字以 `P-`（压力）、`T-`（温度）开头的列会进检验。

| 名字 | 是什么 |
|---|---|
| PDG | 井底的永久压力计，装在井的最下面 |
| TPT | 采油树上的温压传感器（采油树是装在海底井口上的一组阀门） |
| PCK | 生产油嘴，一个控制产量的节流阀 |
| GLCK | 气举油嘴，控制往井里注气的阀门（往井里注气，帮助把油「托」上来，叫气举） |
| MON / JUS | 葡萄牙语的「上游 / 下游」，比如 `T-JUS-CKP` = 生产油嘴下游的温度 |
| ANULAR | 环空，井的内管和外管之间那圈空间 |

下面这些**不进检验**，正好可以拿来独立判断「运行状态有没有变」：

| 名字 | 是什么 |
|---|---|
| ESTADO-* | 各个阀门的状态，取值 0、0.5、1（大致是关、半开、开） |
| ABER-CKP | 生产油嘴开了多大（%） |
| QGL | 往井里注气的流量 |

## 3. 检验为什么报警（已经说清）

- **29.2% 是怎么来的**：先算每条记录各自被拒的比例，再对 16 条取平均。如果直接数窗口，是 300 / 1354 = 22.2%。而且很集中：被拒最多的 5 条记录就占了 229 个。
- **主要是「平均水平」变了**：300 个被拒窗口里，267 个差得最远的特征是均值。也就是说，**大多数情况是某个温度或压力的平均值和前面相比挪了一点**，而不是出现了奇怪的波动形状。
- **少数是「波动节奏」变了**：15 个是自相关变了，其中 13 个来自同一口井 WELL-00014。

## 4. 判断用的四个选项，以及各自的线索

先解释四个选项是什么意思：

- **良性漂移**：设备正常运行时，数值自己慢慢挪了一点（比如温度慢慢升高零点几度），没出任何问题。
- **工况改变**：操作人员动了东西，比如开关了阀门、调了油嘴。数据确实变了，但这是人为调整，不是故障。
- **数据问题**：传感器坏了，或者记录的数本身不可信。
- **其他**：上面三种都不像。

| 选项 | 线索 | 要注意的地方 |
|---|---|---|
| **良性漂移** | 有的变化非常小也被拒了。例如 25 号井井底温度的中位数从 61.26 °C 变成 61.27 °C，只差 0.01 度，一半的窗口都被拒 | 0.01 度在工程上算不算正常波动，要你来判断 |
| **工况改变** | 阀门状态几乎没动过：被拒的 300 个窗口里，只有 1 个窗口内阀门变过；没被拒的 1054 个里是 0 个 | 16 条记录里只有 3 条的阀门在 fit 段和 verification 段不一样，而且都发生在故障开始前最后一两分钟；有 8 条记录没记油嘴开度 |
| **数据问题** | ① 6 号井两条记录里，井底压力一直是 −1.18 × 10⁴²，这在物理上不可能，是坏值；② 19 号井（2012 那条）的井底压力偶尔突然掉到 100 bar 以下，含这种尖刺的窗口被拒 4/25，不含的 0/203 | 6 号井的坏值是一个**一直不变的常数**，而这条记录里差得最远的是另一个传感器（气举油嘴下游的压力）。坏值有没有间接影响检验，还没查 |
| **其他** | ① 有些曲线是由一段段直线拼起来的。真实传感器总有噪声，很少画出完全的直线，所以这很可能是缺了数据后用直线补上的；② 1 号井（2014 那条）的油嘴下游温度从大约第 9.2 小时开始一路往上爬，一直爬到 t_p，被拒的窗口也从那附近开始。**如果故障其实在 t_p 之前就开始了，那这段上升可能本身就是真前兆，只是专家把 t_p 标晚了** | 两种都只是图上看到的现象，没有验证 |

### 7.3 误报率到底是多少

- 论文的 29.2% = 16 条记录各自被拒率的**平均**（每条记录权重一样）。按窗口合起来算是 22.2%（300 / 1354），中位数 14.0%
- 扣掉 25 号井关油嘴那 13 个窗口：29.2% → 29.0%，22.2% → 21.4%。标签 / 工况问题几乎解释不了这个数
- 记录之间差别很大：6 条 ≤ 5%，4 条在 5–20%，6 条 > 35%
- 按每段正常数据的长度分：不到 2 小时的 7 条，平均 45.4%、中位数 37.8%；3.5 小时以上的 8 条，中位数 6.9%，其中两条偏高（25 号井 50.5% 漂移，1 号井 2014 69.1% 插值直线）。这是 16 条记录上的事后观察，只能当待验证的猜测
- 不能事后挑掉「表现差的记录」再报一个更低的数，那是 HARKing。要得到能对外说的数，得先定好排除规则（比如正常段至少多长、插值成直线的通道怎么剔），预注册后在全部 47 次故障上跑

### 7.4 还缺的一步：「假 t_p」检查

要分清「越靠近 t_p 越多报警」是前兆还是漂移，可以在正常段够长的记录上，把 t_p 假装提前几个小时，只用假 t_p 之前的数据重做一遍三等分：
- 朝着假 t_p 也出现同样的上升 → 是漂移和设计本身造成的
- 只有朝着真 t_p 才上升 → 和真实事件有关
